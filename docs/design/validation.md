# 验证

本页定义 DLsim 的预测怎样被检验、哪些数据可以用于检验，以及实现的步骤和每一步的验收条件。

## 原则

预测性验证要求被预测的数据在建模和定参时没有被查看过。已经查看过的数据只能用于开发期诊断，不能作为验收依据。

对照基准：AISimulate 自己公布的端到端误差为 TTFT MAPE 48.5%、TPOT MAPE 28.9%，DeepSeek-V4-Pro 上 TPOT MAPE 73.4%（覆盖率 52.9%）。它使用同一份算子数据，因此这组数字是这条技术路线在绝对值上可达到精度的参照。DLsim 的验收以系统之间的比值和排序为主，绝对值为辅。

## 三层验证

```
第一层  算子级    留一器件     检验跨器件缩放分解
第二层  系统级    留一拓扑     检验单步时延与状态引擎, 器件固定为 GB300
第三层  系统级    跨器件       检验整条正向路径对新器件的预测
```

### 第一层：算子级留一器件

对每个有实测数据的器件 d，用其余器件拟合 a、b、c，预测 d 上的时延，与 d 的实测比较。比较限定在同一框架与版本、同一 kernel 族、同一 dtype 内。

输出按算子类别、dtype 和 shape 区间给出误差分布，以及预测区间覆盖实测值的比例。设计矩阵条件数过大的组合单独列出。

这一层不依赖任何系统级数据，不存在数据泄漏。它直接回答定位中的第 4 点：对没有实测的器件，外推误差有多大。

FP4 的实测只存在于 Blackwell 系列，可用的参考器件数少于 BF16 和 FP8，预期区间更宽。

### 第二层：GB300 留一拓扑

InferenceX 快照中 GB300 在 AgentX 上有 27 个点，分属 dynamo-trt（6）、dynamo-sglang（7）、dynamo-vllm（14）三个框架和多种拓扑。器件的算子时延全部来自实测表，因此这一层的误差来自单步组合、调度、缓存和通信模型。

stack 配置中不能由 recipe 直接读出的参数（每步固定开销、MTP 接受长度）在一部分拓扑上标定，在留出的拓扑上预测整条并发曲线。

标定顺序：先用 dynamo-sglang 的 7 个点，其 attention 查询全部落在 SGLang 0.5.14 表的实测范围内；dynamo-trt 的 6 个点和 dynamo-vllm 的 14 个点同时检验序列轴外推规则和各自框架的 stack 参数。agentic-aggregates 的 prefixCacheHitRate 只有 vLLM 系的行有，dynamo-vllm 的 14 个点可以用它直接核对缓存模型的命中率。

### 第三层：系统级跨器件

在 GB300 上标定的 stack 参数冻结后，用 B200、B300、GB200、H200 各自的实测算子表预测它们的 AgentX 点，与快照比较。

匹配条件：模型、精度、框架、spec_method、是否 P/D 分离、offload 模式、拓扑和并发数全部一致。不满足的点不参与比较。

| 数据 | 状态 |
| --- | --- |
| GB300 的 27 个点 | 已逐行查看，用于第二层的标定与留出，留出的划分在查看曲线形状之前确定 |
| VR200 的 6 个点 | 已逐行查看，只用于诊断 |
| B300、H200 的行 | 曾在探索阶段整体打印过，未逐点分析；第三层使用时注明部分泄漏 |
| B200、GB200 的行 | 只统计过数量 |
| MI355X 的 36 个点 | 只统计过数量；没有该器件的算子数据，kernel 族与参考器件不同，不满足缩放分解的适用条件，只作诊断 |
| 2026-09-20 快照（benchmarks、derived-agentic-metrics、agentic-aggregates） | 只统计过数量；数值只查看了 gb300 dynamo-trt 的一行（id 440971） |
| request-timeline id 440971 | 查看了字段结构和一条 warmup 请求的样本值，未分析 |

VR200 不能作为验收对象还有三个与泄漏无关的原因：公开的 VR200 点 offload 关闭而拓扑相同的 GB300 点 offload 开启；两者的并发数不同；derived-agentic-metrics 对 6 个 VR200 点没有返回值，规范指标无法比较。在拓扑相同的两组点上，VR200 与 GB300 的 ITL 口径 interactivity 之比为 1.83 和 1.90，这一数字只能用于检查 DLsim 的预测方向和量级。

## 冻结清单

第二层的留出部分和第三层在运行前，先向仓库提交一份清单，内容为：全部配置文件的路径、标定得到的参数值、参与比较的点的标识、误差的定义和接受条件。比较结果在其后的提交中加入。两次提交在 git 历史中的先后顺序就是冻结的证据。

冻结之后如果修改了模型再重跑，结果必须标注为冻结后修订，并保留修订前的结果。

## 误差定义

在匹配的并发点上比较：每器件吞吐、P90 E2E normalized interactivity、P90 ITL 口径 interactivity、TTFT 中位数。每个量给出相对误差。

系统之间的比较用比值误差：预测的两系统指标之比除以实测之比。

接受条件的建议值如下，需要仓库所有者在第一次冻结之前确认或修改：

| 层 | 建议的接受条件 |
| --- | --- |
| 第一层 | 对一个算子类别，留一器件的中位相对误差不超过 25%，且预测区间覆盖实测值的比例不低于 80%；不满足的类别在该器件类型上只输出上下界 |
| 第二层 | 留出拓扑上，吞吐与 interactivity 的中位相对误差不超过 AISimulate 公布的 TPOT MAPE（28.9%）；曲线的形状（吞吐随并发的饱和点）位置误差在一个并发档位以内 |
| 第三层 | 系统两两之间的比值误差中位不超过 20%；系统的排序与实测一致 |

不满足时的处理不是调整参数直到通过，而是把该类配置的输出降级为区间或 unsupported，并记录原因。

## 实现步骤与验收

每一步的完成声明必须同时具备三样东西：提交到仓库的产物路径、产生它的命令及退出码、由独立 agent 在干净检出上重跑得到相同结论的记录。

| 步骤 | 内容 | 验收条件 | 能发现的错误 |
| --- | --- | --- | --- |
| 1 | trace 加载、二进制缓存、session 依赖图 | 计数与 token 总量等于数据集 `stats.txt`（393 session，98,827 请求，输入 21,635,381,376，输出 106,474,498）；依赖图与 agentx-harness 加载器对同一批 trace 的输出一致（会话数、请求序列、依赖边）；理论前缀命中率按全局时间顺序重算 | 字段语义误读；subagent 与展平 agent 的识别规则实现错误 |
| 2 | 导入工具、算子表、插值 | 导入后的行数等于源 parquet；精确命中返回实测值；留一插值的中位误差落在 AISimulate 公布的范围内（GEMM 3.6% 到 4.9%，context attention 约 2.0%，DSA 约 5.4%）；attention 序列轴外推规则：把 SGLang 0.5.14 的 dsv4 表截断到 65,536，按规则外推，与 65,536 到 1,048,576 的实测行比较并给出误差分布，通过后才用于 TRT-LLM 与 vLLM 的表 | 键列丢失；版本复用规则解析错误；插值轴选择错误；外推的代价结构写错 |
| 3 | 跨器件缩放分解 | 产出第一层验证报告；Bw 一列秩亏的 dtype（当前为 FP4 的 GEMM 与 MoE）按 [operator-latency.md](operator-latency.md) 的区间规则单独报告 | 分解形式不适用的算子类别；秩亏未被检出 |
| 4 | DeepSeek-V4-Pro 算子图、单步时延 | 算子清单与参考文件逐项核对的记录；权重字节数与模型公开的参数规模一致；GB300 上若干 (batch, context) 点与 AISimulate 对同一配置的静态预测对照，差异逐算子解释 | 漏算子；并行下 shape 推导错误；通信消息大小错误 |
| 5 | 状态引擎 | 同一输入与种子两次运行的输出逐字节相同；每个被准入的请求都结束或被报告；容量无限时的缓存命中率等于理论前缀命中率；单 session 无竞争时 TTFT 等于对应的单步时延之和 | 事件顺序不确定；请求丢失；缓存匹配规则错误；时钟推进错误 |
| 6 | InferenceX 行输出 | 字段与快照中的行一致；用一份手工构造的逐请求记录核对每个指标的计算结果；用 request-timeline 的逐请求记录（id 440971）重算该点的两种 interactivity，与 benchmarks 行的 p90_intvty 和 derived-agentic-metrics 的 p90_e2e_norm_intvty 一致 | 指标定义错误，尤其是两种 interactivity 的混淆 |
| 7 | 第二层与第三层验证 | 冻结清单先提交，验证报告后提交 | 正向路径的系统性偏差 |
| 8 | fabric 与异构器件组 | S 不小于并行组规模时结果等于单域结果；L 不受限且 alpha 为零时结果等于无通信结果；用 AISimulate 的通信表与 CollectiveX 的 EP8 行标定 alpha_up 与 L_up，按域溢出规则预测 CollectiveX 的 EP16 行并给出误差报告，其中 4 节点 MNNVL 的行检验单域等价，2 节点跨 RDMA 的行检验域溢出计价；EP32 与跨机柜标注为未验证 | 域溢出计价错误；跨域流量比例错误 |
| 9 | 反向求解 | 回收测试：取已知的 x0，算出 y0 = f(x0)，固定其余参数后反求某一参数的阈值，结果在网格分辨率内回到 x0；人为放入一个指标不敏感的参数（例如部署完全落在单域内时的 L_out），必须被标注为不可辨识 | 搜索方向错误；可辨识性分析失效 |

步骤 1 和步骤 4 中用到的 agentx-harness 与 AISimulate 是 Python 程序。它们只在 `third_party` 中作为参照工具被运行一次以产生对照数据，不属于 DLsim 的代码，也不是 DLsim 的运行依赖。

## 当前无法验证的部分

| 部分 | 原因 | 后果 |
| --- | --- | --- |
| 多机柜部署的系统级结果 | 公开数据中没有超出单个 scale-up 域的 AgentX 点 | 算子级对照只有 CollectiveX 的 2 节点跨 RDMA EP16 行，跨机柜没有实测；结果标注为未经系统级验证 |
| 没有 HBM 的器件 | 参考器件全部使用 HBM 或 GDDR；缩放分解中的 Bw 外推到 LPDDR 量级超出参考范围 | 输出区间而不是点估计；这是接入使用 LPDDR 类主存的器件时的主要风险 |
| 异构器件组 | 没有公开的异构 AgentX 部署数据 | 只能验证各器件组单独的结果和交付链路的极限情形 |
| MTP 接受长度 | recipe 给出草稿长度，不给接受长度 | 作为标定参数，在第二层中与每步固定开销一起确定，两者可能不可区分，需要报告 |
