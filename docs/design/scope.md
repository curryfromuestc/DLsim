# 范围与已定决定

## 要回答的问题

给定一个用配置描述的推理网络和一份真实的云端 agentic 负载，回答两类问题。

正向问题：该网络在给定 SLO 下的系统指标是多少，与 GB300 NVL72 等有公开实测的系统相比差多少，时间消耗在哪一种资源上（算力、存储带宽、存储容量、scale-up 互联、scale-out 互联）。

反向问题：为了在某个指标上达到给定目标，器件参数、互联参数和软件栈特性各自需要满足什么条件。

DLsim 内部不设任何算力或带宽上限。器件的全部特性来自配置。

## 定位

1. 输入是 AgentX trace，重放语义与 agentx-harness 一致；输出的指标定义和行格式与 InferenceX 一致，可以与公开曲线直接叠加。
2. 器件的算子时延按算子类别、dtype 和 shape 给出，不使用单一的利用率标量。
3. 硬件是变量。支持带物理耦合约束的反向求解。
4. 对没有实测数据的器件，用跨器件缩放分解给出带不确定度的预测，并用已有实测的器件做留一验证来量化外推误差。

## 已定决定

| 决定 | 内容 |
| --- | --- |
| 仓库 | DLsim 是独立仓库；使用它的项目以 git submodule 引用 |
| 语言 | C++20，单一语言；不使用 Python 和 Rust |
| 与 AISimulate 的关系 | 只使用它的实测算子数据，并把它的代码作为算法参考；不链接、不调用它的代码 |
| 实现顺序 | 先实现通用功能，对象是有公开数据的 NVIDIA 系统和假想器件 |
| 第一个模型 | DeepSeek-V4-Pro，FP4 权重，FP8 KV |

## 范围内

AgentX 重放、逐请求的单步时延、多级 KV 缓存、P/D 分离与 KV 交付、KV 感知路由、MTP、scale-up 与 scale-out 互联、多机柜部署、异构器件组、InferenceX 格式输出、三层验证、反向求解（含物理耦合约束和成本目标）。

## 推迟

| 项目 | 推迟到什么条件满足 |
| --- | --- |
| 自定义器件接入 | 该器件的推理框架支持补全之后。届时算子时延由它的周期级性能模型给出，格式沿用本仓库的算子表 schema，不使用 RTL 仿真 |
| 以 Vera Rubin（VR200）实测为对象的验收 | 出现尚未查看过的新数据之后。现有 6 个 VR200 点已被查看过，只能用于开发期诊断，见 [validation.md](validation.md) |

## 不做

包级网络仿真、HTTP 与操作系统调度、tokenizer、prompt 文本内容、单个 kernel 内部的微观执行。这些分别属于网络模拟器、服务框架和芯片级性能模型的范围。

不支持的配置开关必须显式报错，不能静默退化为默认行为。

## 对结果的表述要求

所有结果以区间或带来源标注的点估计给出。超出数据覆盖范围的查询返回上下界或 unsupported，不返回没有依据的点估计。
