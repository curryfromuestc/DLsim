# 反向求解

本页定义反向问题的形式、求解方法、可辨识性分析和物理耦合约束。

## 问题形式

正向仿真是一个函数

```
y = f(x; w)
x: 设计变量   器件参数, fabric 参数, mapping 参数, stack 开关
w: 固定输入   模型, trace, SLO 定义
y: 指标       InferenceX 行中的各量, 成本, 功耗
```

反向问题不是求 f 的逆。满足一个指标目标的 x 通常是一个集合，而不是一个点。因此反向求解的输出有三种形式，由用户选择：

| 形式 | 输入 | 输出 |
| --- | --- | --- |
| 可行集 | 指标约束 y ≥ y_target，变量范围，耦合约束 | 可行域的采样和它的边界 |
| 最优点 | 同上，加一个标量目标（例如每百万 token 成本、器件数、功耗） | 最优的 x 及其邻域内的灵敏度 |
| Pareto 前沿 | 两个或多个目标 | 非支配解的集合 |

没有目标函数也没有要求可行集的反向查询会被拒绝，因为它没有确定的答案。

指标目标可以是绝对值，也可以是相对某个参照系统的比值，例如在相同 SLO 下每器件吞吐不低于 GB300 NVL72 的某个倍数。参照系统的数值来自 InferenceX 快照或 DLsim 对该系统的正向仿真，两者必须注明。

## 条件阈值

单个参数的要求只在其他参数固定时才有意义。输出的表述形式是条件式的：

```
在 mapping = M, stack = S, 其他器件参数 = x_rest 的条件下,
指标达到 y_target 要求 存储带宽 ≥ B*
```

同时给出 B* 对 x_rest 中每个量的灵敏度。不输出脱离条件的单一数字。

## 设计变量

| 类别 | 变量 |
| --- | --- |
| 器件 | 各精度算力、各级存储的容量与带宽、scale-up 端口带宽、功耗、单价 |
| fabric | S、L_up、alpha_up、L_out、alpha_out、r |
| mapping | 器件数、prefill 与 decode 的配比、TP、EP、DP attention、worker 数 |
| stack | 特性开关，离散变量 |

mapping 与 stack 是内层变量：对每个候选的器件与 fabric，先在 mapping 上取最优，再比较。否则比较的是 mapping 的好坏，不是器件的好坏。

## 求解方法

两级精度。第一级用闭式估算在整个变量空间上筛选，代价为微秒级，可以做稠密网格。第二级只对第一级保留的候选运行完整重放。

第二级的搜索用确定性的方法：连续变量用坐标方向的二分与网格细化求边界，离散变量枚举。单次重放在秒级，256 核的机器上一轮可并行评估数百个点，因此第一阶段不引入代理模型和贝叶斯优化。如果变量维数增长到网格不可行，再评估是否需要。

指标对多数器件参数是单调的（算力、带宽、容量增大不会使指标变差）。二分法依赖这一性质。单调性在运行时检查：相邻网格点出现反向变化时报告，该维度改用网格。

## 可辨识性

反向求解给出的参数要求，只在指标对该参数敏感时才有意义。对每个解计算灵敏度矩阵

```
J_ij = d log y_i / d log x_j        用中心差分, 在解的邻域内
```

并报告：

| 量 | 含义 |
| --- | --- |
| J 的每一列的范数 | 接近零的列对应指标不敏感的参数，对它不能给出要求 |
| J 的奇异值与条件数 | 小奇异值对应的参数组合方向不可由这些指标区分 |
| 近似共线的列 | 这些参数只能作为组合给出要求，例如只能约束 C 与 B 的某个加权组合 |

不敏感或不可区分的参数在输出中明确标注为不可辨识，不给阈值。

差分的步长要大于仿真的离散化噪声。重放在固定随机种子下是确定的，但 t* 采样和调度的离散性使指标对参数不连续。步长默认取 5%，并用多个种子的平均。

## 物理耦合约束

器件参数不能独立取值。耦合约束由用户在配置中以不等式给出，DLsim 不内置具体工艺的数值。约束的形式：

| 约束 | 形式 | 物理来源 |
| --- | --- | --- |
| 芯片边缘 | w_mem × 主存带宽 + w_io × 互联带宽 ≤ 边缘长度预算 | 主存 PHY 与 SerDes 共用芯片边缘 |
| 面积 | 算力对应的面积 + PHY 面积 + 其他 ≤ die 面积预算 | 光罩尺寸与良率 |
| 功耗 | 算力功耗 + 存储接口功耗 + 互联功耗 ≤ TDP | 封装与散热 |
| 容量与带宽 | 容量 = 通道数 × 每通道容量，带宽 = 通道数 × 每通道带宽 | 主存类型决定每通道的容量带宽比 |
| 成本 | 单价 = g(die 面积, 主存类型与容量, 封装) | 由用户给出的成本模型 |

系数 w、每通道的容量与带宽、成本模型全部来自配置并注明来源。没有给出的约束不生效，输出中列出哪些约束未启用。

容量与带宽约束对主存类型的比较是关键的：每通道容量大而带宽低的主存，使容量与带宽沿一条固定斜率的线变化，与 HBM 的斜率不同。反向求解在这条线上移动，而不是在整个平面上移动。

## 成本目标

成本目标的默认形式是给定 SLO 下每百万 token 的成本：

```
cost = ( 器件数 × 单价 / 折旧时长 + 功耗 × 电价 × PUE + 互联与机柜成本 ) / 吞吐
```

所有系数来自配置，参照系统一侧也是。InferenceX 的 `/api/v1/tco-feed` 不含成本假设，只是按 interactivity 档给出的吞吐前沿，见 [data-sources.md](data-sources.md)。

## 输出

每个反向查询输出：查询的完整定义、可行集或最优解或前沿、每个解的灵敏度矩阵与可辨识性标注、启用和未启用的约束、每个被评估点的正向结果。被评估点全部保存，使任何结论都可以追溯到具体的正向运行。

## 前提

反向求解的可信度不超过正向模型的可信度。对某类器件，正向模型在 [validation.md](validation.md) 的验证中得到的误差区间，直接传递到反向求解的参数要求上。参数要求的输出带有这一区间。
